## Chapter 7: AI Incident Response, Audit, and Assurance — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | Four main categories of AI incidents the exam tests? | 1) Discriminatory outcomes, 2) Privacy breaches, 3) Safety failures, 4) Adversarial attacks. Exam tip: Know specific examples of each - e.g., discriminatory = biased hiring, privacy = model inversion attack, safety = autonomous vehicle crash, adversarial = prompt injection. |
| 2 | AI incident response workflow - exact 5 steps in order? | 1) CONTAIN (stop the harm), 2) INVESTIGATE (root cause), 3) REMEDIATE (fix it), 4) DOCUMENT (record everything), 5) REPORT (if required). Exam tip: ALWAYS contain first before investigating. Common mistake: jumping to investigation while harm continues. |
| 3 | Five root cause categories for AI incidents? | 1) Data issues, 2) Model drift, 3) Adversarial input, 4) Deployment error, 5) Human oversight failure. Exam tip: Questions will describe an incident and ask you to identify root cause category. Data issues and model drift are most common on exam. |
| 4 | Four ways AI incidents are detected? | 1) User complaints, 2) Monitoring alerts, 3) Regulatory inquiry, 4) Media reports. Exam tip: Monitoring alerts = proactive detection (best case). User complaints/media/regulatory = reactive detection (incident already causing harm). |
| 5 | Three types of AI audits and what each covers? | 1) ALGORITHMIC audits (model fairness, accuracy), 2) PROCESS audits (governance compliance), 3) CONFORMITY assessments (regulatory compliance). Exam tip: Question will describe audit scope - match to correct type. 'Third-party' describes WHO, not WHAT type. |
| 6 | What defines an AI incident vs normal system behavior? | Any of: 1) Harm caused by AI system, 2) Deviation from expected behavior, 3) Regulatory violation. Exam tip: Even if 'working as designed,' if it causes harm = incident. Even if no harm YET, if violates regulation = incident. |
| 7 | Three post-incident actions required after AI incident? | 1) Model retraining (with improvements), 2) Policy updates (to prevent recurrence), 3) Affected party notification (if harm occurred). Exam tip: Notification often legally required for privacy breaches. Policy updates must address root cause. |
| 8 | Internal audit vs third-party audit - which is required when? | INTERNAL: Regular monitoring, can be done by company staff, less credible externally. THIRD-PARTY: Required for regulatory compliance (EU AI Act), conformity assessment, higher credibility, independent verification. Exam tip: High-risk AI systems typically require third-party audits. |
| 9 | What documentation must be preserved for AI regulatory inquiries? | 1) Model training logs, 2) Inference logs for specific incidents, 3) Model version metadata, 4) Change management records, 5) Governance meeting minutes, 6) Previous audit reports. Exam tip: Technical logs prove what model did. Process docs prove governance existed. |
| 10 | Model drift as root cause - what is it and how detected? | Production data distribution differs from training data, causing performance degradation. Detected via: monitoring accuracy by demographic/condition, tracking prediction distribution over time, comparing production vs validation metrics. Exam tip: Model drift ≠ model decay. Drift = data changed, decay = model itself degraded. |
| 11 | Privacy breach incident - what triggers mandatory notification? | Exposure of personal data through: model inversion, membership inference, training data extraction. Must notify: affected individuals, supervisory authority (if GDPR), may need public disclosure. Exam tip: Threshold = likelihood of harm to individuals, not number affected. |
| 12 | Adversarial attack vs deployment error as root cause - how to distinguish? | ADVERSARIAL: Malicious input designed to trick model (intentional). DEPLOYMENT: Wrong config/version/environment (accidental). Exam tip: If attack is external/intentional = adversarial. If internal mistake = deployment error. Both cause deviation from expected behavior. |
