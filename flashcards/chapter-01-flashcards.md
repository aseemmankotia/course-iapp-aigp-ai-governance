## Chapter 1: Foundations of AI Systems for Governance — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | EU AI Act: Provider vs Deployer - who ensures conformity assessment is completed? | Provider ensures conformity assessment (Article 16). Deployer ensures appropriate deployment, monitoring, and human oversight (Article 26). Both have obligations but provider handles technical compliance, deployer handles operational compliance. Exam tip: Questions often test whether deployer can skip checks because provider did conformity assessment - WRONG, deployer has separate duties. |
| 2 | 2026 BoK shift: AI Model vs AI System - what's included in 'AI system' that's NOT in 'AI model'? | AI system includes: model + data pipelines + user interfaces + deployment infrastructure + monitoring systems + governance controls. AI model = trained algorithm only. Exam tip: System-level risks (data drift, interface misuse, infrastructure failure) differ from model-level risks (bias, accuracy). Governance must address BOTH levels. |
| 3 | Foundation model - definition and governance implication | Foundation model: large model trained on broad data, adapted for multiple downstream tasks (e.g., GPT-4, DALL-E). Governance implication: Need controls at TWO levels - base model (training data, capabilities) AND each use case (fine-tuning, deployment context). Exam tip: Fine-tuning a foundation model doesn't exempt from governance - new risks emerge at application layer. |
| 4 | Training data governance vs Inference data governance - key difference | Training data: focus on representativeness, bias detection, quality, labeling accuracy. Inference data: focus on drift monitoring, input validation, adversarial attack detection, distribution shifts. Exam tip: Both need privacy controls, but training needs historical quality checks while inference needs real-time monitoring. |
| 5 | EU AI Act Article 23: Importer obligations (name 3) | 1) Verify CE marking exists 2) Ensure provider completed conformity assessment 3) Maintain technical documentation 4) Register high-risk systems 5) Comply with deployer obligations when using system. Exam tip: Importer = gatekeeper for non-EU AI entering market. Can't just trust provider - must verify compliance. |
| 6 | EU AI Act Article 24: Distributor obligations (name 2) | 1) Verify CE marking present 2) Check provider/importer fulfilled obligations 3) Ensure proper storage/transport preserves compliance 4) Cooperate with authorities. Exam tip: Distributor doesn't redo conformity assessment but must verify it was done. Think: quality gatekeeper, not quality creator. |
| 7 | Supervised vs Unsupervised vs Reinforcement Learning - governance difference | Supervised: labeled data governance (bias in labels, data quality). Unsupervised: pattern validity (are clusters meaningful?). Reinforcement: safety constraints on exploration (prevent harmful trial-and-error). Exam tip: Reinforcement learning in production = highest real-time safety risk due to learning by trying actions. |
| 8 | General-Purpose AI (GPAI) - what makes it 'general-purpose' and why governance cares | GPAI = AI system that performs various tasks without specific design for one application (foundation models are GPAI). Governance cares because: single GPAI system used in multiple contexts (some high-risk, some not) requires risk assessment per deployment context, not just once. Exam tip: GPAI in high-risk use = high-risk obligations apply. |
| 9 | AI system components - name all 4 core components | 1) Data (training + inference) 2) Model (algorithm/weights) 3) Interface (API/UI for interaction) 4) Deployment environment (infrastructure, monitoring). Exam tip: Governance failures often occur at component boundaries - data quality issues, interface misuse, infrastructure failures. Assess risks across ALL components, not just model. |
| 10 | Can one organization have multiple EU AI Act roles (provider, deployer, importer)? | YES. Example: Company imports base model from US (importer), fine-tunes it creating new system (provider), deploys it in their operations (deployer). Each role carries distinct obligations under Articles 16, 23, 26. Exam tip: Don't assume one company = one role. Map activities to roles, not companies to roles. |
| 11 | Deep Learning vs Machine Learning - governance distinction | Machine Learning = algorithms that learn from data (includes simple models). Deep Learning = ML using neural networks with multiple layers (subset of ML). Governance distinction: Deep learning typically less interpretable (black box) requiring additional explainability controls. Exam tip: All deep learning is ML; not all ML is deep learning. Risk-based governance, not technology-based. |
| 12 | AI vs Machine Learning vs Deep Learning - hierarchy for non-technical stakeholders | AI (broadest): systems that perform tasks requiring human-like intelligence. ML (subset): AI that learns from data without explicit programming. Deep Learning (subset): ML using multi-layer neural networks. Think: AI > ML > Deep Learning (nested sets). Exam tip: Questions test whether you understand these are nested categories, not separate technologies. |
